# مرجع API — حساب الزبون (التسجيل · الدخول · رمز التحقق · استعادة كلمة السر)

> مرجع لمطوّر تطبيق الموبايل. كل الردود في هذا الملف **ملتقَطة فعلياً من الكود الحالي** بنداءات حقيقية على الخادم، لا مكتوبة يدوياً.
>
> آخر تحديث: ١٦ آب ٢٠٢٦.

---

## القاعدة الذهبية — متى يُرسَل رمز التحقق؟

رمز واتساب يُرسَل في **حالتين فقط**:

| الحالة | لماذا |
|---|---|
| **التسجيل** | لإثبات ملكية الرقم مرة واحدة، فيُفتح الحساب |
| **نسيت كلمة السر** | لإثبات ملكية الرقم قبل تغيير كلمة السر |

**تسجيل الدخول لا يُرسل أي رمز إطلاقاً.** بعد أن يُوثَّق الرقم مرة واحدة عند التسجيل، كل دخول لاحق هو **رقم الهاتف + كلمة السر** فقط، ويرجع التوكن مباشرة — بلا شاشة رمز، بلا انتظار رسالة.

```
مرة واحدة عند إنشاء الحساب:   تسجيل ← رمز واتساب ← الحساب يُنشأ ويدخل التطبيق مباشرة
كل دخول بعد ذلك:              رقم + كلمة سر ← توكن     (بلا رمز)
لو نسي كلمة السر لاحقاً:       رقم ← رمز واتساب ← كلمة سر جديدة ← يسجّل دخول
```

> **مبدأ مهم:** الحساب **لا يُنشأ إلا بعد نجاح الرمز**. التسجيل يحفظ البيانات مؤقتاً (١٠ دقائق) ويرسل الرمز؛ لحظة إدخال الرمز الصحيح **يُولَد الحساب مفعّلاً ويدخل التطبيق فوراً بتوكن**. فلا توجد حالة «بانتظار التوثيق» ولا حساب معلّق أبداً.

## ١. الأساسيات

**الرابط الأساسي:**
```
https://servix.diyala.org/api/v1
```

**الترويسات:**

| الترويسة | القيمة | متى |
|---|---|---|
| `Accept` | `application/json` | دائماً — بدونها يرجع HTML |
| `Content-Type` | `application/json` | مع كل `POST` |
| `Authorization` | `Bearer <token>` | المسارات المحمية 🔒 فقط |

**شكل الرد موحّد دائماً:**

```jsonc
// نجاح
{ "success": true,  "message": "نص عربي جاهز للعرض", "data": … }

// فشل
{ "success": false, "message": "نص عام", "errors": { "الحقل": ["الرسالة"] } }
```

> عند `422` اعرض `errors[field][0]` تحت كل حقل. الرسالة العامة `message` للإشعارات فقط.
> بعض الأخطاء (رمز واتساب) تضع الرسالة تحت `errors.otp`، وبعضها (عطل الخدمة) يرسلها في `message` مع `errors: []` — انظر جدول الحالات لكلٍّ منها.

**رقم الهاتف** يُقبل بثلاث صيغ ويُخزَّن ويُرجَع دائماً بالصيغة الدولية:

| ما ترسله | ما يرجع |
|---|---|
| `07710000001` · `+9647710000001` · `9647710000001` | `9647710000001` |

**أكواد الحالة:**

| الكود | المعنى | تصرّف التطبيق |
|---|---|---|
| `200` | نجاح | اقرأ `data` |
| `201` | أُنشئ (التسجيل) | انتقل لشاشة الرمز |
| `401` | توكن مفقود أو منتهٍ | امسح التوكن وارجع لشاشة الدخول |
| `409` | تعارض — العملية نُفّذت مسبقاً (نقرة مزدوجة) | اعرض `message`، لا تُعد الإرسال |
| `422` | بيانات مرفوضة أو رمز خاطئ | وزّع `errors` على الحقول |
| `503` | خدمة الرسائل متعطّلة | اعرض `message` كـ«حاول لاحقاً»، لا تلوّن الحقول |

## ٢. الخط الأول — التسجيل (خطوتان)

```
شاشة إنشاء حساب ──POST /register──▶ شاشة رمز التحقق ──POST /verify-otp──▶ الرئيسية (يدخل مباشرة)
```

التسجيل **لا ينشئ حساباً** — يحفظ البيانات بالكاش ويرسل الرمز. لحظة إدخال الرمز الصحيح يُنشأ الحساب `active` ويرجع **توكن**، فيدخل الزبون التطبيق مباشرة. ماكو حالة معلّقة، ماكو توثيق كحالة.

### 2.1 `POST /customer/auth/register` 🌐

قبلها حمّل القوائم: `GET /customer/governorates` ثم `GET /customer/governorates/{id}/districts` (القضاء يتبع المحافظة).

**الطلب:**
```json
{
  "name": "مصطفى علي حسن",
  "gender": "male",
  "phone": "07710000001",
  "password": "hoame-2026",
  "password_confirmation": "hoame-2026",
  "governorate_id": 1,
  "district_id": 1,
  "terms_accepted": true
}
```

| الحقل | القيد |
|---|---|
| `name` | مطلوب · ٣–٢٥٥ حرفاً |
| `gender` | مطلوب · `male` أو `female` |
| `phone` | مطلوب · رقم عراقي |
| `password` | مطلوب · ٨–٦٤ خانة · مع `password_confirmation` |
| `governorate_id` | مطلوب · محافظة مفعّلة |
| `district_id` | مطلوب · قضاء مفعّل تابع للمحافظة المرسلة |
| `terms_accepted` | مطلوب · `true` |

**`201` — البيانات حُفظت والرمز انطلق (لا حساب بعد):**
```json
{
  "success": true,
  "message": "أرسلنا رمز التحقق إلى واتساب",
  "data": {
    "phone": "9647710000001",
    "resend_in": 59
  }
}
```
> **لا يوجد توكن، ولا حساب بعد.** احفظ `data.phone`، انتقل لشاشة الرمز، وابدأ عدّاداً تنازلياً بـ`resend_in` ثانية. البيانات محفوظة مؤقتاً ١٠ دقائق فقط.

**`422` — حقول مرفوضة:**
```json
{
  "success": false,
  "message": "البيانات المدخلة غير صحيحة",
  "errors": {
    "name": ["الاسم قصير جداً"],
    "phone": ["رقم الهاتف غير صحيح، مثال: 07712345678"],
    "password": [
      "كلمة السر يجب أن تكون 8 أحرف على الأقل",
      "تأكيد كلمة السر غير مطابق"
    ]
  }
}
```

**`422` — الرقم يخصّ حساباً موجوداً:**
```json
{
  "success": false,
  "message": "البيانات المدخلة غير صحيحة",
  "errors": { "phone": ["رقم الهاتف مسجّل بالفعل، سجّل الدخول أو استعد كلمة السر"] }
}
```

**`422` — أُرسل رمز قبل أقل من ٦٠ ثانية** (لو أعاد إرسال نموذج التسجيل بسرعة):
```json
{
  "success": false,
  "message": "انتظر 58 ثانية قبل إعادة إرسال الرمز",
  "errors": { "otp": ["COOLDOWN"] }
}
```

**التوجيه:**

| الرد | إلى أين |
|---|---|
| `201` | ← شاشة رمز التحقق (مع `data.phone` وعدّاد `resend_in`) |
| `422` رقم موجود | ابقَ، واعرض زر «تسجيل الدخول» |
| `422` حقول | ابقَ، وزّع الأخطاء على الحقول |

> **ملاحظة:** أي رقم يخصّ حساباً موجوداً يُرفض. ورقم بدأ تسجيلاً ولم يكمل الرمز ليس له صفّ بقاعدة البيانات — بياناته بالكاش فقط وتنتهي خلال ١٠ دقائق.

### 2.2 `POST /customer/auth/verify-otp` 🌐 — يُنشئ الحساب ويدخل

**الطلب:**
```json
{ "phone": "07710000001", "code": "123456" }
```
> `code` يجب أن يكون **٦ أرقام بالضبط**.

**`201` — أُنشئ الحساب `active` ومعه توكن (يدخل التطبيق مباشرة):**
```json
{
  "success": true,
  "message": "تم إنشاء حسابك بنجاح",
  "data": {
    "user": {
      "id": 40,
      "name": "مصطفى علي حسن",
      "phone": "9647710000001",
      "status": "active",
      "status_label": "نشط",
      "governorate": { "id": 1, "name": "بغداد" },
      "district": { "id": 1, "name": "مركز بغداد" },
      "deletion_requested": false,
      "created_at": "2026-08-16T18:00:00+03:00"
    },
    "token": "210|xxxxxxxxxxxxxxxxxxxxxxxx",
    "token_type": "Bearer"
  }
}
```
> **احفظ التوكن وادخل التطبيق مباشرة** — ماكو شاشة دخول للمستخدم الجديد.

**`422` — رمز خاطئ:**
```json
{ "success": false, "message": "الرمز غير صحيح", "errors": { "otp": ["INVALID_CODE"] } }
```

**`422` — صيغة الرمز خاطئة (ليس ٦ أرقام):**
```json
{
  "success": false,
  "message": "البيانات المدخلة غير صحيحة",
  "errors": { "code": ["الرمز يتكوّن من ٦ أرقام"] }
}
```

**`422` — انتهت جلسة التسجيل** (مرّت ١٠ دقائق أو أُعيد التطبيق):
```json
{
  "success": false,
  "message": "البيانات المدخلة غير صحيحة",
  "errors": { "phone": ["انتهت جلسة التسجيل، أعد إدخال بياناتك"] }
}
```

**التوجيه:**

| الرد | إلى أين |
|---|---|
| `201` | احفظ `token` و`user` ← **الرئيسية مباشرة** |
| `422` `INVALID_CODE` | ابقَ، أفرغ حقل الرمز |
| `422` `EXPIRED_CODE` | ابقَ، فعّل زر «إعادة الإرسال» |
| `422` انتهت الجلسة | ← أعِده لشاشة إنشاء الحساب |

### 2.3 `POST /customer/auth/resend-otp` 🌐 — زر «لم يصلني الرمز»

يخدم **شاشتَي الرمز** (التسجيل والاستعادة). إذا كان هناك تسجيل قيد التنفيذ بالكاش → رمز تسجيل؛ وإلا → رمز استعادة لحساب موجود. النوع يصلك في `data.purpose`.

**الطلب:** `{ "phone": "07710000001" }`

**`200` — تسجيل قيد التنفيذ (رمز تسجيل):**
```json
{
  "success": true,
  "message": "تم إرسال رمز جديد",
  "data": { "phone": "9647710000010", "purpose": "register", "resend_in": 59 }
}
```

**`200` — حساب موثّق (رمز استعادة):**
```json
{
  "success": true,
  "message": "تم إرسال رمز جديد",
  "data": { "phone": "9647710000011", "purpose": "reset", "resend_in": 59 }
}
```

| `data.purpose` | متى | يفتح |
|---|---|---|
| `register` | تسجيل قيد التنفيذ بالكاش | `verify-otp` |
| `reset` | حساب موجود (استعادة) | `reset-password` |

**`422` — رقم بلا حساب:**
```json
{ "success": false, "message": "البيانات المدخلة غير صحيحة", "errors": { "phone": ["لا يوجد حساب بهذا الرقم"] } }
```

**`422` — قبل انتهاء المهلة:**
```json
{ "success": false, "message": "انتظر 58 ثانية قبل إعادة إرسال الرمز", "errors": { "otp": ["COOLDOWN"] } }
```

## ٣. الخط الثاني — تسجيل الدخول (بلا رمز)

المكان الوحيد الذي يخرج منه توكن. **لا يُرسَل أي رمز هنا** — رقم + كلمة سر فقط. احفظ التوكن في مخزن آمن (Keychain / EncryptedSharedPreferences).

### 3.1 `POST /customer/auth/login` 🌐

**الطلب:**
```json
{ "phone": "07710000001", "password": "hoame-2026" }
```

**`200`:**
```json
{
  "success": true,
  "message": "تم تسجيل الدخول بنجاح",
  "data": {
    "user": {
      "id": 38,
      "name": "مصطفى علي حسن",
      "gender": "male",
      "phone": "9647710000001",
      "status": "active",
      "status_label": "نشط",
      "governorate_id": 1,
      "governorate": { "id": 1, "name": "بغداد" },
      "district_id": 1,
      "district": { "id": 1, "name": "مركز بغداد" },
      "deletion_requested": false,
      "deletion_requested_at": null,
      "created_at": "2026-08-16T15:49:27+03:00"
    },
    "token": "202|mGauPFx6W1ivaPEqY8Ab2mve8FsSKUCKYRz4azRB983acc15",
    "token_type": "Bearer"
  }
}
```

**`422` — رقم أو كلمة سر خاطئة:**
```json
{
  "success": false,
  "message": "البيانات المدخلة غير صحيحة",
  "errors": { "phone": ["رقم الهاتف أو كلمة السر غير صحيحة"] }
}
```

**`422` — محاولات دخول كثيرة** (بعد ٥ محاولات خاطئة على نفس الرقم خلال ١٠ دقائق):
```json
{
  "success": false,
  "message": "البيانات المدخلة غير صحيحة",
  "errors": { "phone": ["محاولات دخول كثيرة، حاول بعد 599 ثانية"] }
}
```
> الحدّ يعدّ **المحاولات الخاطئة فقط**، والكلمة الصحيحة تصفّر العدّاد — فالمستخدم الصادق لا يُقفل أبداً بدخوله الصحيح مهما تكرّر. لكن بعد بلوغ الحدّ حتى الكلمة الصحيحة تُرفَض حتى تمرّ المهلة (حماية من التخمين).

**`422` حسب حالة الحساب** — انظر **§٦ حالات الحساب**.

**التوجيه:**

| الرد | إلى أين |
|---|---|
| `200` | احفظ `token` و`user` ← الرئيسية |
| `422` كلمة سر خاطئة | ابقَ |
| `422` لم يتم التوثيق | ← شاشة رمز التحقق (نادِ `resend-otp` أولاً) |
| `422` غير مفعّل / مجدول للحذف | ابقَ، اعرض الرسالة |

### 3.2 `GET /customer/auth/me` 🔒 — عند فتح التطبيق

إن كان التوكن محفوظاً، تحقّق منه قبل عرض الرئيسية.

**`200` — نفس حقول `user` ومعها `orders_count`:**
```json
{
  "success": true,
  "message": "User retrieved successfully",
  "data": {
    "id": 38,
    "name": "مصطفى علي حسن",
    "gender": "male",
    "phone": "9647710000001",
    "status": "active",
    "status_label": "نشط",
    "governorate_id": 1,
    "governorate": { "id": 1, "name": "بغداد" },
    "district_id": 1,
    "district": { "id": 1, "name": "مركز بغداد" },
    "orders_count": 0,
    "deletion_requested": false,
    "deletion_requested_at": null,
    "created_at": "2026-08-16T15:49:27+03:00"
  }
}
```

**`401` — توكن مفقود أو منتهٍ:**
```json
{ "success": false, "message": "Unauthorized", "errors": [] }
```
> **قاعدة عامة:** أي `401` من **أي** نداء يعني الجلسة انتهت — امسح التوكن وانقل الزبون لشاشة الدخول فوراً. لا يوجد `refresh` لواجهة الزبون.

### 3.3 `POST /customer/auth/logout` 🔒

يُلغي التوكن الحالي فقط — بقية أجهزة الزبون تبقى داخلة.

**`200`:**
```json
{ "success": true, "message": "تم تسجيل الخروج بنجاح", "data": null }
```

## ٤. الخط الثالث — نسيت كلمة السر (٣ خطوات)

```
شاشة «نسيت كلمة السر» ──POST /forgot-password──▶ شاشة الرمز وكلمة السر الجديدة ──POST /reset-password──▶ شاشة الدخول
```

الطريق الوحيد الذي يعود فيه الرمز بعد التسجيل. إعادة التعيين **لا ترجع توكناً** وتُلغي كل جلسات الحساب.

### 4.1 `POST /customer/auth/forgot-password` 🌐

**الطلب:** `{ "phone": "07710000001" }`

**`200`:**
```json
{
  "success": true,
  "message": "أرسلنا رمز استعادة كلمة السر إلى واتساب",
  "data": { "phone": "9647710000001", "resend_in": 59 }
}
```

**`422` — رقم بلا حساب:**
```json
{ "success": false, "message": "البيانات المدخلة غير صحيحة", "errors": { "phone": ["لا يوجد حساب بهذا الرقم"] } }
```

**`422` — حساب موقوف / مجدول للحذف:** لا يُرسَل رمز لحساب لا يقدر يدخل به — رسالة «حسابك غير مفعّل، راجع الإدارة» أو «حسابك مجدول للحذف».

### 4.2 `POST /customer/auth/reset-password` 🌐

**الطلب:**
```json
{
  "phone": "07710000001",
  "code": "123456",
  "password": "hoame-2027",
  "password_confirmation": "hoame-2027"
}
```
> `code` ٦ أرقام بالضبط · `password` ٨–٦٤ خانة مع تأكيدها.

**`200` — `data` فارغة، ولا توكن:**
```json
{
  "success": true,
  "message": "تم تغيير كلمة السر، سجّل الدخول بكلمتك الجديدة",
  "data": null
}
```
> كل جلسات الحساب تُلغى على كل الأجهزة. انتقل لشاشة الدخول ليُثبت كلمته الجديدة.

**`422` — رمز خاطئ:**
```json
{ "success": false, "message": "الرمز غير صحيح", "errors": { "otp": ["INVALID_CODE"] } }
```

**التوجيه:**

| الرد | إلى أين |
|---|---|
| `200` | ← شاشة الدخول |
| `422` `INVALID_CODE` | ابقَ، أفرغ الرمز |
| `422` `EXPIRED_CODE` | ابقَ، فعّل زر «إعادة الإرسال» |

## ٥. تغيير كلمة السر (وهو داخل)

مختلف عن الاستعادة: **بلا رمز**، ويحتاج كلمة السر الحالية. من شاشة «الملف الشخصي ← الأمان».

### `POST /customer/profile/change-password` 🔒

**الطلب:**
```json
{
  "current_password": "hoame-2026",
  "password": "hoame-2027",
  "password_confirmation": "hoame-2027"
}
```
> `password` ٨–٦٤ خانة، مع تأكيدها، ويجب أن تختلف عن الحالية.

**`200`:**
```json
{
  "success": true,
  "message": "تم تغيير كلمة السر، وسُجّل الخروج من بقية الأجهزة",
  "data": null
}
```

**`422` — كلمة السر الحالية خاطئة:**
```json
{
  "success": false,
  "message": "البيانات المدخلة غير صحيحة",
  "errors": { "current_password": ["كلمة السر الحالية غير صحيحة"] }
}
```

> **الفرق عن الاستعادة:** هنا الجهاز الحالي **يبقى داخلاً** وتموت بقية الأجهزة فقط. في `reset-password` تموت كل الجلسات بلا استثناء.

## ٦. طلب حذف الحساب

طلب يُسجَّل لدى الإدارة، **لا حذف فوري**. لا شيء يُمسح: الحساب وطلباته يبقيان حتى تقرّر الإدارة. الحالة تصير `scheduled_for_deletion` والجلسة تُغلق فوراً.

### `POST /customer/profile/delete-request` 🔒

بلا جسم طلب. اعرض حوار تأكيد قبل ندائه.

**`200`:**
```json
{
  "success": true,
  "message": "تم إرسال طلب الحذف إلى الإدارة",
  "data": null
}
```

**بعده مباشرة — أي نداء بالتوكن القديم `401`:**
```json
{ "success": false, "message": "Unauthorized", "errors": [] }
```

**عند محاولة الدخول لاحقاً — `422`:**
```json
{
  "success": false,
  "message": "البيانات المدخلة غير صحيحة",
  "errors": { "phone": ["حسابك مجدول للحذف"] }
}
```

**التوجيه:**

| الرد | ماذا يعرض التطبيق | إلى أين |
|---|---|---|
| `200` | اعرض `message`، ثم امسح التوكن والبيانات المحلية | ← شاشة الدخول |
| `401` بعده | الجلسة انتهت | ← شاشة الدخول |

> **لا تنادِ `logout` بعده** — الخادم ألغى كل توكنات الحساب مع الطلب نفسه، فأي نداء تالٍ (بما فيه إعادة الطلب) يرجع `401`.
>
> **البيانات محفوظة:** الحساب وطلباته وسجلّه تبقى في اللوحة، والإدارة تقدر تسحب الطلب فيعود الحساب `active` ويدخل الزبون بكلمة سرّه نفسها.

## ٧. مرجع أخطاء رمز واتساب — `errors.otp[0]`

هذه تصل في `errors.otp` مع `422`، **عدا أعطال الخدمة** فتصل في `message` مع `503` و`errors: []`.

| الرمز | الرسالة العربية من الخادم | الكود | تصرّف التطبيق |
|---|---|---|---|
| `INVALID_CODE` | الرمز غير صحيح | 422 | أعِد الإدخال |
| `EXPIRED_CODE` | انتهت صلاحية الرمز، اطلب رمزاً جديداً | 422 | أظهر زر «إرسال رمز جديد» |
| `COOLDOWN` | انتظر N ثانية قبل إعادة إرسال الرمز | 422 | العدد داخل `message`، عطّل الزر |
| `INVALID_PHONE` | رقم الهاتف غير صحيح | 422 | تحت حقل الهاتف |
| `INVALID_OTP_FORMAT` | الرمز يتكوّن من ٦ أرقام | 422 | تحقّق من الطول |
| `NOT_CONFIGURED` / `MISSING_API_KEY` / `INVALID_API_KEY` | خدمة الرسائل غير مهيّأة، راجع الإدارة | **503** | «حاول لاحقاً» — العطل عند الإدارة |
| `INSUFFICIENT_CREDITS` | رصيد الرسائل غير كافٍ، راجع الإدارة | **503** | «حاول لاحقاً» |
| `SERVICE_UNAVAILABLE` | خدمة الرسائل غير متاحة حالياً، حاول لاحقاً | **503** | «حاول لاحقاً» |

**مثال عطل الخدمة `503`** (تعذّر الوصول إلى مزوّد الرسائل، أو غير مهيّأ):
```json
{
  "success": false,
  "message": "خدمة الرسائل غير متاحة حالياً، حاول لاحقاً",
  "errors": []
}
```
> ملاحظة: `503` رسالتها في `message` و`errors` فارغة — **لا تلوّن حقل الرمز بالأحمر**، اعرضها كانقطاع خدمة مؤقّت. مدّة صلاحية الرمز ١٠ دقائق.

## ٨. حالات الحساب — `user.status`

كل ردّ يحمل بيانات المستخدم يحوي `status` و`status_label` (جاهزة للعرض). الحالة تُقرأ **عند الدخول فقط**، ولذلك تُلغى كل توكنات الحساب لحظة خروجه من `active`.

| `status` | `status_label` | متى تصير | الدخول | رسالة الرفض عند الدخول |
|---|---|---|---|---|
| `active` | نشط | لحظة إنشاء الحساب (بعد الرمز) | ✅ | — |
| `inactive` | غير نشط | أوقفته الإدارة | ❌ | «حسابك غير مفعّل، راجع الإدارة» |
| `suspended` | موقوف | أوقفته الإدارة | ❌ | «حسابك غير مفعّل، راجع الإدارة» |
| `scheduled_for_deletion` | مجدول للحذف | طلب الزبون حذف حسابه | ❌ | «حسابك مجدول للحذف» |

> **الحساب يُولَد `active` دائماً** — ما يوجد إلا بعد نجاح الرمز، فماكو حالة معلّقة ولا مفهوم توثيق منفصل.

**أمثلة ردود الدخول حسب الحالة (كلها `422`):**

```jsonc
// inactive / suspended
{ "success": false, "message": "البيانات المدخلة غير صحيحة",
  "errors": { "phone": ["حسابك غير مفعّل، راجع الإدارة"] } }

// scheduled_for_deletion
{ "success": false, "message": "البيانات المدخلة غير صحيحة",
  "errors": { "phone": ["حسابك مجدول للحذف"] } }
```

**كيف يتصرّف التطبيق:**

| الحالة | التصرّف |
|---|---|
| `inactive` / `suspended` | اعرض الرسالة، وجّهه لمراجعة الإدارة |
| `scheduled_for_deletion` | حوار: «حسابك مجدول للحذف»، وللتراجع راجع الإدارة |

> ما توجد حالة «قيد الانتظار» ولا «بانتظار التوثيق». الحساب يُنشأ `active` مباشرة بعد الرمز.

## ٩. خريطة التوجيه بين الشاشات

```
┌─────────────────┐   201    ┌─────────────────┐  201+توكن  ┌──────────┐
│  إنشاء حساب     │ ───────▶ │  رمز التحقق     │ ─────────▶ │ الرئيسية │   (المستخدم الجديد يدخل مباشرة)
│  /register      │          │  /verify-otp    │           │          │
└─────────────────┘          └────────┬────────┘           └──────────┘
   (لا حساب بعد —                     │ resend-otp (purpose=register)
    البيانات بالكاش)                  ▼
                              زر «لم يصلني الرمز»

┌──────────────┐  200+توكن  ┌──────────┐
│  تسجيل الدخول │ ─────────▶ │ الرئيسية │   (المستخدم العائد: رقم + كلمة سر، بلا رمز)
│  /login       │           │          │
└──────────────┘           └──────────┘

┌──────────────────┐  200   ┌────────────────────────┐  200 (بلا توكن)  ┌──────────────┐
│ نسيت كلمة السر   │ ─────▶ │ الرمز + كلمة سر جديدة  │ ───────────────▶ │ تسجيل الدخول │
│ /forgot-password │        │ /reset-password        │                  │  /login       │
└──────────────────┘        └────────────────────────┘                  └──────────────┘
```

## ١٠. مرجع سريع

| النقطة | الوصول | يرسل رمزاً؟ | يرجع توكناً؟ | الشاشة التالية |
|---|---|---|---|---|
| `POST /customer/auth/register` | 🌐 عام | ✅ نعم | ❌ لا | رمز التحقق |
| `POST /customer/auth/verify-otp` | 🌐 عام | ❌ | ✅ **نعم** | الرئيسية مباشرة |
| `POST /customer/auth/resend-otp` | 🌐 عام | ✅ نعم | ❌ لا | نفس شاشة الرمز |
| `POST /customer/auth/login` | 🌐 عام | ❌ **لا** | ✅ نعم | الرئيسية |
| `GET /customer/auth/me` | 🔒 توكن | ❌ | ❌ | الرئيسية أو الدخول |
| `POST /customer/auth/logout` | 🔒 توكن | ❌ | ❌ | تسجيل الدخول |
| `POST /customer/auth/forgot-password` | 🌐 عام | ✅ نعم | ❌ لا | شاشة الرمز |
| `POST /customer/auth/reset-password` | 🌐 عام | ❌ | ❌ **لا** | تسجيل الدخول |
| `POST /customer/profile/change-password` | 🔒 توكن | ❌ | ❌ | نفس الشاشة |
| `POST /customer/profile/delete-request` | 🔒 توكن | ❌ | ❌ | تسجيل الدخول |

**الخلاصة:** الحساب يُولَد فقط بعد نجاح الرمز (لا حالة معلّقة أبداً). المستخدم الجديد يدخل التطبيق مباشرة بعد الرمز، والعائد يدخل برقم + كلمة سر بلا رمز.
